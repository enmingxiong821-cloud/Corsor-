### 0.1 一个必须先纠正的认知

这台机器**已经装了官方中文语言包，覆盖率 85.43%**。所以本项目的命题不是
"从零开始汉化"，而是：

> **补齐 14.57% 的缺口，并保证从此不再因 Cursor 升级而失效。**

---

## 1. 三条核心结论（先行）

**结论一：Cursor 的本地化通道是官方机制，不是外挂。**
`workbench.js` 中 `setupNLS()` 把语言包消息注入 `globalThis._VSCODE_NLS_MESSAGES`，
且 `workbench.desktop.main.js` 内保留完整的 `contributes.localizations`、
`languagePack`、`resolvedLanguage` 加载逻辑。语言包在 Cursor 中是**一等公民**。
→ 因此主线方案应是"做一个更完整的语言包"，而非"改程序"。

**结论二：覆盖率的缺口主要来自"路径漂移"，不是"没翻译"。**
实测语言包中**没有** `vs/workbench/electron-sandbox/desktop.contribution`，
却**存在** `vs/workbench/electron-browser/desktop.contribution`。
上游 VS Code 把 `electron-browser` 目录重命名为 `electron-sandbox` 后，
译文与模块 ID 对不上号，整模块归零。
→ 只需一层**路径归一化映射表**即可零成本救回 2.45 个百分点。

**结论三：语言包无法覆盖 Cursor 专有 UI，这是硬边界。**
Cursor 的智能体面板、设置页、插件市场由 React / SolidJS 硬编码渲染，
**不经过 NLS**。同类项目为此维护了约 **3,100 条词条 + 239 条正则规则**。
→ 要做到"接近全中文"，必然需要一个**运行时文本层**。

## 4. 关键约束与实测结论

### 4.1 完整性校验（最高优先级风险）

`product.json.checksums` 保护 6 个文件：

```
vs/base/parts/sandbox/electron-sandbox/preload.js
vs/workbench/workbench.desktop.main.js
vs/workbench/workbench.desktop.main.css
vs/workbench/api/node/extensionHostProcess.js
vs/code/electron-sandbox/workbench/workbench.html   ← 注入点
vs/code/electron-sandbox/workbench/workbench.js
```

**实测结论（已复现全部 6 项）**：算法为
`base64(SHA-256(文件字节)).replace(/=+$/, "")`，即标准 SHA-256 的 Base64 编码并**去掉 `=` 填充**。

```
workbench.html 实测 059f196f... → BZ8Zb4TGBbDPaaGjA+MuDJxaFsxjmmG0YMyttD4zgcU
product.json 期望 BZ8Zb4TGBbDPaaGjA+MuDJxaFsxjmmG0YMyttD4zgcU   ✓ MATCH
```

→ **只要改文件后同步重算对应校验值，Cursor 不会报"installation appears to be corrupt"。**
这是注入方案能否成立的关键，现已验证通过。

> 注意：`resources/app/` 是解包目录而非 `app.asar`，因此不涉及 Electron 的
> asar integrity 校验，改文件本身无需解包，风险面进一步收窄。

### 4.2 CSP：注入必须是外部同源脚本

`workbench.html` 的 CSP 中：

```
script-src 'self' 'unsafe-eval' blob:;     ← 没有 'unsafe-inline'
```

→ **禁止内联 `<script>`**。注入只能采用：
① 同源外部文件 `<script src="./X.js" type="module">`（推荐）；
② blob URL（`blob:` 被允许）。

### 4.3 Trusted Types：不能用 innerHTML

```
require-trusted-types-for 'script';
trusted-types amdLoader cellRendererEditorText ... dompurify safeInnerHtml ...;
```

策略白名单**不含通配符**，第三方脚本无法自建任意名称的 policy。

→ **文本层必须只使用 `textContent` / 文本节点操作，禁用 `innerHTML`、`outerHTML`、`insertAdjacentHTML`。**
这一约束直接决定引擎实现方式（见 §5.3）。

### 4.4 版本漂移

Cursor 每次升级都可能改变：键表内容、模块路径、CSP、校验值。
→ 词典与映射表**不得硬编码版本**，必须由"扫描 → 对齐 → 生成"的流水线产出。

### 4.5 性能

同类项目的全文档 `MutationObserver(childList+subtree)` 在 Cursor 编辑器高频
输入 / 大文件渲染场景下会反复触发全树扫描，存在掉帧风险。
→ 本蓝图要求：观察域限定、批处理、节点去重、空闲调度（见 §5.3）。

### 4.6 隐私与合规

本方案**不联网、不上传任何用户数据**，词典全部本地生成，无遥测。

### 4.7 免校验通道（实测新增）

`product.json.checksums` 仅覆盖 6 个文件。以下目标**不在校验范围**：

| 文件 | 大小 | 用途 |
| --- | ---: | --- |
| `out/vs/workbench/workbench.glass.main.js` | 47.4 MB | 智能体窗口（Agents Window） |
| `out/vs/workbench/workbench.anysphere-ui-automations.js` | 8.9 MB | Automations 界面 |
| `out/nls.messages.json` | 665 KB | 主进程消息表（原生菜单 / 托盘） |

→ 智能体窗口与主进程文案属于**低风险改造区**；主 workbench 必须走"改写 + 重算校验"。

## 5. 设计蓝图

### 5.0 分层架构总览

```
        ┌──────────────────────────────────────┐
        │  L3  运行时文本层（可选，需注入）     │  C 层硬编码文案
        │      XsRuntime.js  → textContent     │
        ├──────────────────────────────────────┤
        │  L2  缺口补译（零侵入）               │  B 层 + A 层残余
        │      自建语言包 cursor-zh-hans        │
        ├──────────────────────────────────────┤
        │  L1  键表对齐引擎（零侵入）           │  A 层主体
        │      官方语言包 + 路径归一化映射      │
        ├──────────────────────────────────────┤
        │  L0  备份 / 还原 / 校验管理           │  安全底座
        └──────────────────────────────────────┘
```

**原则：默认只启用 L0+L1+L2。L3 为可选增强，单独开关，可独立回退。**

### 5.1 L0 安全底座

- **改动前强制备份**：任何被写入的文件先复制到 `backup/<timestamp>/`，
  并记录原始 SHA-256，支持按 hash 精确还原。
- **幂等标记**：注入内容携带 `data-xs-injection="cursor-zh@<version>"`，
  重复执行只更新不叠加（同类项目用 `findstr` 标记，本项目用结构化标记）。
- **一次性还原**：`取消汉化` 恢复全部备份文件、重算校验值、移除注入标记；
  语言包扩展可保留（无副作用）。
- **零改动的默认路径**：L1/L2 完全不触碰 Cursor 安装目录。

### 5.2 L1 键表对齐引擎（核心，零侵入）

**输入**

| 来源 | 用途 |
| --- | --- |
| `out/nls.keys.json` | Cursor 该版本的**权威键清单**（13,530 键） |
| `out/nls.messages.json` | 逐位对应的英文原文 |
| 官方 `main.i18n.json` | 基线译文（命中率 85.43%） |

**算法**

```
for each (moduleId, messageKey) in nls.keys.json:
    zh = official[moduleId][messageKey]
    if zh is missing:
        for v in normalizeVariants(moduleId):        # 路径归一化
            zh = official[v][messageKey]; break
    if zh is still missing:
        zh = supplement[moduleId][messageKey]        # L2 补译
    emit(moduleId, messageKey, zh ?? skip)
```

**路径归一化映射表**（v1，来自实测，可扩展）

| 上游旧路径 | Cursor 新路径 |
| --- | --- |
| `electron-browser` | `electron-sandbox` |
| `contrib/search/common` | `contrib/search/browser` |

实测该映射可救回 **332 键**（**映射上限**）；实现时 4 条因占位符不匹配被闸拒，
**净救回 328 键、覆盖率 87.86%** —— 见 `docs/05` §4。

**产出**：一个标准语言包扩展

```
cursor-zh-hans/
├── package.json          # publisher=cursor-zh-local, 无 marketplace 依赖
├── translations/
│   ├── main.i18n.json    # 对齐后的完整译文
│   └── extensions/*.i18n.json
└── README.md
```

`package.json` 骨架（字段来自实测的官方语言包）：

```json
{
  "name": "cursor-language-pack-zh-hans",
  "publisher": "cursor-zh-local",
  "version": "1.0.0",
  "engines": { "vscode": "^1.128.0" },
  "categories": ["Language Packs"],
  "contributes": {
    "localizations": [{
      "languageId": "zh-cn",
      "languageName": "Chinese Simplified",
      "localizedLanguageName": "中文(简体)",
      "translations": [{ "id": "vscode", "path": "./translations/main.i18n.json" }]
    }]
  }
}
```

**为什么这一层是安全的**

- 不写入 Cursor 安装目录 → 不触发校验
- 不受 Cursor 升级影响 → 升级后重跑生成器即可
- 卸载扩展即完全还原
- 走官方 `contributes.localizations` 通道，等价于 VS Code 的语言包

### 5.3 L2 缺口补译

缺口必须区分两个口径：

- **严格净缺口 1,127 键** —— 连"同名键的参考译文"都不存在，必须真正翻译。
- **待补译总量 1,639 键** —— 含 512 个"键名在官方语言包别处出现过"的键，可复用现成译文、只需核对语义。

实测分档（全部为脚本统计，非估算）：

| 档位 | 内容 | 待补译 | 其中严格缺口 | 处理 |
| --- | --- | --- | --- | --- |
| P0 必译 | Cursor 专有 UI：智能体 / Composer / 布局 / Blame / Origin / 认证 | 311 | 297 | 人工精译 |
| P1 应译 | 标准 VS Code 功能文案 | 903 | 448 | 复用官方译文 + 校正 |
| P2 可缓 | 开发者与内部功能：实验开关、性能分析、工具宿主 | 317 | 305 | 机器翻译 / 暂缓 |
| P3 忽略 | 测试模块（运行时不可见） | 108 | 77 | 不译 |

P0 档的 297 个严格缺口几乎全部落在 Cursor 自研模块上，印证了
"官方语言包永远不会覆盖 Cursor 专有 UI"的判断——这部分只能自建。

工作单已由 `tools/gap3.mjs` 导出至 `build/missing.json`。

**翻译质量守则**

- 保留 `{0}` `{1}` 占位符与 `&&` 助记符（`miExit = "E&&xit"`）
- 不译专有名词：Cursor / Composer / MCP / Token / Commit / Pull Request / Git
- 术语统一表：Agent→智能体、Rules→规则、Skills→技能（**完整表以 [`data/terms.json`](../data/terms.json) 为准**）
  - 注意 `Composer` **不译**（译「编辑器」会与 VS Code 原生 Editor 冲突）
  - `Tab` / `Blame` 是歧义词须分治，详见 04 文档 §5

### 5.4 L3 运行时文本层（可选，需注入）

仅在用户要求"界面接近全中文"时启用。工程要求：

**注入方式**

```
workbench.html  追加：<script src="./XsZhRuntime.js" type="module"></script>
                标记：data-xs-injection="cursor-zh@<ver>"
product.json    重算 workbench.html 的 checksum（base64 SHA-256 去 padding）
```

**性能设计（相对同类方案的改进点）**

| 要点 | 做法 |
| --- | --- |
| 观察域收敛 | 优先挂载到 `#workbench\.parts\.*` 等已知容器，避免 `documentElement` 全树 |
| 回调批处理 | MutationObserver 回调只入队，用 `requestIdleCallback` / `rAF` 合并 |
| 节点去重 | 已处理文本节点记入 `WeakSet`，不重复比对 |
| 短路 | 若文本无 ASCII 字母则直接跳过（中文/数字/符号无需处理） |
| 词典结构 | `Map<string,string>` 精确匹配 + 少量正则规则表（仅动态文本） |
| 上限保护 | 单次批处理限制节点数，超限拆帧 |

**安全约束**

- 只用 `textContent` 赋值（Trusted Types 下 innerHTML 会抛错）
- 仅改写**文本节点**，绝不替换元素结构，避免打断 React/SolidJS 的 diff
- 不处理 `input` / `textarea` / 编辑器正文 / 终端内容（防止污染代码）
- 跳过用户内容区：`[contenteditable]`、`.monaco-editor`、`code`、`pre`

**词典组织**（借鉴并改进同类项目）

```
dict/
├── ui.json          # [英文, 中文] 精确匹配表
├── patterns.json    # {regex, flags, replacement} 动态文本（数量/时间/计数）
└── scope.json       # 分区开关（模块级启停）
```

**覆盖目标（实测校验状态）**

| 目标 | 文件 | 校验状态 |
| --- | --- | --- |
| 主界面 | `out/vs/workbench/workbench.desktop.main.js` | 需重算校验 |
| 智能体窗口 | `out/vs/workbench/workbench.glass.main.js` | 免校验 |
| 主进程菜单 / 托盘 | `out/nls.messages.json` | 免校验 |

**必须一并处理：界面缓存**

Cursor 会把界面文案状态缓存进 `%APPDATA%\Cursor\User\globalStorage\state.vscdb`。
补丁生效后界面仍是英文，通常是该缓存在起作用 → 部署流程必须包含缓存清理。

**事务与回滚（借鉴社区最严方案）**

- 输出先在内存生成并校验；任一步失败按反向顺序恢复本次改动
- `product.json` 校验值**只在文件写入成功后**更新
- 备份按 `version + distro` 分目录，避免用旧备份覆盖新 bundle
- 还原前比对哈希；被升级器改过的文件跳过，不用旧备份强覆盖
- 升级跟随：启动后校验版本与已改文件哈希，有变化才重打；无法可靠翻译的新增文案写入报告，不盲翻
