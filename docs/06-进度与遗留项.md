### §2.1 事故记录：3.27.22 适配后的黑屏（2026-11-01）

**现象**：`sync` 完成后 Cursor 启动即黑屏，两个窗口全黑，日志无 integrity/corrupt 报错。

**根因**（带 `--enable-logging` 启动后从控制台抓到）：

```
[uncaught exception]: Error: Semantic ladder has no row for bg危险主要
Uncaught (in promise) Error: cursor semantic: missing ref "red前景"
```

`semantic-ladders.js` 里有两张表的**值既是显示名又是拼键标识符**：

| 表 | 拼出来的键 | 后果 |
| --- | --- | --- |
| `{red:"Red",…,danger:"Danger",primary:"Primary",…}`（21 成员） | `` bg${tone}${variant} `` → `bg危险主要` | 色阶查不到 → 抛异常 |
| `{text:"Foreground",icon:"ForegroundBright",border:"Fill"}` | `` ${color}${kind} `` → `red前景` | 引用查不到 → 抛异常 |

工作台初始化中断 → 整窗黑屏。**标识值守卫挡不住这一类**：它们不参与等值比较，
只参与字符串拼接，静态扫描时看不出「这个值会被拼进键」。

**修复**：① 值全落在色阶词汇集且 ≥8 成员的映射表整块跳过（`SEMANTIC_TOKEN_VALUES`）；
② `semantic-ladders.js` 整块不翻（`MODULE_DENY`）；③ 模块标记正则不能写死 loader 名
——glass 用 `L(`、内核用 `W(`，写死 `L(` 会让内核那份整块漏掉。

**教训**：任何「显示名同时当标识符」的表都可能在别处以拼接形式出现；
新版本适配后必须真机启动一次并检查控制台异常，不能只看 `verify 6/6` 与语法检查。

### §2.2 同一轮补上的设置页说明（规则 ⑪）

设置项说明普遍写成 `description:\`…${u}\``，前十条规则只认引号字面量，整批漏在英文。
新增规则 ⑪ 后，玻璃目标多收 **14 条**模板文案。三条安全边界都是实测踩出来的：

- **只翻设置类模块**（`TEMPLATE_MODULE_ALLOW`）：同样的形状在 `telemetry-log.ts` 里是
  **喂给模型的工具说明**（"Read the written chat in this agent…"），翻掉会改模型行为；
- **`${…}` 必须逐字保留**：曾把槽位里的条件文案也翻掉，被 `slotsMatch` 正确丢弃
  —— 宁可留英文，也不生成坏模板；
- **模板边界用 `${}` 深度切分**（`scanTemplates`），不用正则配对 —— 嵌套模板
  （`` `a${b?`c`:`d`}` ``）会让纯反引号配对整片错位，与当年 `LIT` 那个坑同源；
  文件里还有孤立反引号，扫描器必须容错跳过而不是中断。

**刻意保留英文的三处**：`Manage Themes` / `Tool Call Density` / `Submit with Ctrl + Enter`
是设置搜索的**排序索引数组**（`glass-settings-popularity.js`），是匹配用键，翻了会让搜索失灵。

## §3 待办与遗留项

### 3.1 本地可解，但需先设计闸门

**① `CURSOR_DASHBOARD_COPY` 的带空格键** —— `Additional usage credits` /
`Monthly additional usage` / `Set auto top-up`
- **阻塞原因**：这是**键含空格**的映射表。`NAV_MAP_RE` 的键字符类是小写 id、
  `CAMEL_MAP_RE` 要求驼峰键，现有十一条规则一条都匹配不上。
- **下手点**：单开规则 ⑫（新增 `SPACED_MAP_RE`，或在现有键字符类里放开空格）。
  `CLAUDE.md` 明令：**放宽前先按增量重测**。

### 3.2 本地无解（由服务端下发）

**③ 语音模式的那句提示**、**④ `Premium` / `Get more usage with Premium` / `Upgrade to Premium`**
- **阻塞原因**：三个 bundle 里各出现 **0 次**，由服务端下发，语言包也够不着。
- **下手点**：本地无解，只能等 Cursor 自己接入语言包。**不要为凑数字硬造译文。**

### 3.3 已明确不做

**跨平台（macOS / Linux）** —— 2026-10-16 经询问后由用户明确推迟。三个已知阻塞点：
`src/m4/fontfix.mjs` 的 `FONT_STACK` 写死 Windows 字体；入口全是 `install.cmd` / `uninstall.cmd`
与 Windows 计划任务；`src/deploy/process.mjs` 在非 win32 直接返回 `null`，少了「Cursor 在运行
就拒绝写入」这道检查。**不要主动提议做跨平台**，用户要在 Mac 上用再按上面清单做。

**第四个目标 `workbench.xai-commerce-prepaid.js`** —— 免校验，但实测命中 0 条，无需处理。

### 3.4 换 Cursor 版本必重验

同一大版本的补丁版（3.27.x）bundle 主要变 hash，规则基本可沿用。**跨大版本**时
`sync` 虽会自动重跑，但有三条必须重新实证，不能想当然：

- **不能跨版本复用备份**（项目铁律）
- **必须真机启动一次并检查控制台异常**（`--enable-logging` 启动，搜 `uncaught` /
  `Semantic ladder` / `missing ref`）—— `verify 6/6` + 语法检查都过了，仍可能因
  「显示名兼标识符」的表被翻译而在初始化时抛异常 → 黑屏。见 §2.1。
- 覆盖率基准要重算 —— 基准取**备份里的原始英文表**，不是磁盘上当前文件
  （装过之后后者已是中文，当「英文原文」用会凭空报缺口）
- 两条判定会失效，须重跑：① 标识值守卫挡下的那批值；② 计费名单里**刻意保留英文的那三条串**
  （`Share exceeds content limits` / `No response was received within the time limit` /
  `The AI provider is rate-limiting…`），它们是按当前 bundle 逐条核过使用站点得出的结论
