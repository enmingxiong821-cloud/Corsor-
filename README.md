## 结论速览

| 指标 | 实测值 |
| --- | ---: |
| Cursor 版本 | 3.24.18（内核 VS Code 1.128.0） |
| 界面消息键总数 | 13,530 |
| 当前中文覆盖 | 11,559（**85.43%**） |
| 路径漂移可救回 | +332 键 → 87.89% |
| 严格净缺口 | 1,127 键（8.33%） |
| 社区同类方案可达 | **≈ 99.8%** |

三个关键事实：

1. **缺口主因不是"没翻译"，而是模块路径漂移**——上游把 `electron-browser` 改名成 `electron-sandbox`，语言包还按旧路径组织，整模块对不上号。
2. **注入是可行的且可控**——`product.json` 的校验算法已复现（`base64(sha256)` 去 `=` 填充），改写文件后重算即可通过校验。
3. **语言包有硬边界**——Cursor 的智能体面板、设置页、插件市场由 React/SolidJS 硬编码渲染，不走 NLS，约 3,100 条文案必须另想办法。

## 目录结构

```
.
├── README.md                本文件（人类入口）
├── CLAUDE.md                编码代理入口（开工前必读）
├── docs/                    调研与设计文档
│   ├── 01-设计蓝图.md
│   ├── 02-同类项目调研.md
│   ├── 03-技术机制与实测数据.md
│   ├── 04-参考资料与路径索引.md
│   └── 05-开发规格.md        ← 交给编码代理的实现规格
├── tools/                   分析工具（Node ≥ 18，无第三方依赖）
│   ├── gap2.mjs               覆盖率总览 + 缺口模块排行
│   ├── gap3.mjs               展开缺口，导出待翻译工作单
│   ├── map.mjs                路径漂移诊断与救回量化
│   ├── survey.mjs             GitHub 项目批量检索
│   └── gh.mjs                 单仓库检索（tree/file/readme）
├── data/                    开发用输入数据
│   ├── renames.json           路径归一化映射（已填实测值）
│   ├── terms.json             术语表
│   └── overrides.json         补译词典（初始为空）
└── build/                   生成产物
    ├── missing.json           待翻译工作单（按模块分组 + 英文原文）
    ├── all-keys.json          全量 13,530 键 + 英文原文 + 现有译文
    └── survey.json            GitHub 检索原始结果
```

> `src/` 尚未创建 —— 它由编码代理按 `docs/05-开发规格.md` §3 实现。

---

## 使用

```powershell
node tools/gap2.mjs    # 看当前覆盖率与缺口分布
node tools/gap3.mjs    # 导出待翻译工作单到 build/
node tools/map.mjs     # 诊断路径漂移造成的假缺口
```

所有工具**只读** Cursor 安装目录，唯一写入位置是本仓库的 `build/`。
