## 3. 技术路线分类

所有项目可归入三种路线，**没有任何项目只靠单一路线做到高覆盖**。

### 路线 ①：纯语言包（零侵入）

代表：`polang233/cursor-language-pack`、`zhongruan0522/cursor-zh-cn-pack`

- 做法：生成 `.vsix`，走官方 `contributes.localizations` 通道
- 覆盖：菜单、文件、编辑器、终端、设置**框架**
- 天花板：**"设置页、智能体窗口、账号页里写死的英文不会变"**（原作者原话）
- 冲突约束：**`id: vscode` 的语言包不能与官方中文包共存**，同装会导致"重启后翻译会乱"

### 路线 ②：语言包 + 硬编码补丁（主流）

代表：`LoosePrince/cursor-zh-cn-pack`、`lsh2253823857/cursor-i18n-tool`、`moonliere-afk`、`vibepm666`

- 做法：语言包兜底 + 改写 bundle 硬编码字符串 + **同步 `product.json` 校验值**
- 覆盖：可到 ~99%（见 §4.2）
- 代价：升级后失效，须重打补丁；必须处理"installation is corrupt"告警

### 路线 ③：运行时注入（DOM 替换）

代表：`vibepm666`（`Cursor_Localization.js` 注入 `workbench.html`）、`Uncle-Gao/Live-Translator-Hub`

- 做法：`MutationObserver` 监听 DOM，实时替换文本节点
- 优点：不碰程序文件，升级不失效
- 缺点：性能开销、覆盖不稳定、webview 内拿不到

## 4. 重点项目的可借鉴设计

### 4.1 `LoosePrince/cursor-zh-cn-pack` —— 分层最清晰

明确列出四层目标，与本次蓝图的模型高度一致：

| 层级 | 目标文件 | 说明 |
| --- | --- | --- |
| 扩展 NLS | `anysphere.cursor-*` | 走标准 Language Pack 机制 |
| Workbench 硬编码 | `workbench.desktop.main.js` | 设置、Composer、菜单 |
| Agents Window | `workbench.glass.main.js` | 智能体窗口 |
| NLS 消息表 | `nls.messages.json` | 未进扩展包的私有文案 |

值得借鉴的点：

1. **定位为"补充"而非"替代"**——不生成 `main.i18n.json`，避免与官方包冲突
2. 语言包资源**不写安装目录**；只有主动点击"应用汉化补丁"才写入，写入前自动备份
3. 提供 `state.vscdb` 缓存清理（详见 §4.4）
4. 宣称"已在 3.17.8 上验证补丁不会造成 Cursor 无法启动或无法使用"

### 4.2 `polang233/cursor-language-pack` —— 给出了覆盖率实测

- 简体中文工作台：**12726 / 12748 ≈ 99.8%**
- 这证明：**只要键表对齐得当，覆盖率可以接近 100%**，本蓝图早前"92%+"的预期过于保守
- 明确警告两种语言包不能并存
- 提供 `npm run translate` / `--undo`，中文专属说明文档完善

### 4.3 `moonliere-afk/cursor-zh-cn-language-pack` —— 工程严谨度最高

安全设计几乎可以直接作为本项目的规格：

| 机制 | 实现 |
| --- | --- |
| 版本化备份 | 按 `version + distro` 分目录，**不会用旧 `.bak` 覆盖新 bundle** |
| 事务写入 | 先在内存生成并校验，任一步失败则反向恢复；`product.json` 校验和**只在文件写入成功后**才更新 |
| 严格还原 | 还原前比对哈希，被升级器改过的文件**跳过**，不用旧备份强覆盖 |
| 升级跟随 | 启动 5 秒后校验版本与全部已改文件哈希；有变化则后台线程重打 |
| 翻译记忆 | 用官方语言包建立"英文原文 → 官方中文"记忆，自动补全新版本新增文案 |
| 拒绝盲翻 | 无法可靠翻译的新增文案写入 `reports/upgrade-<版本>.json`，不盲目机翻 |

**避免启动卡死的经验（重要）**：

- 不观察、不修改编辑器内部的占位装饰属性
- 不修改 `contenteditable`、输入框、Monaco、终端、聊天消息正文
- **不用 `textContent` 覆盖 React 子树**（只改叶子文本节点）
- 初始扫描使用 `requestIdleCallback`

### 4.4 隐藏坑：`state.vscdb` 里的界面缓存

`LoosePrince` 与 `moonliere-afk` 都提到：Cursor 会把界面文案状态缓存进
`%APPDATA%\Cursor\User\globalStorage\state.vscdb`（SQLite）。
**汉化后若"看起来没生效"，往往需要清理该缓存**——这是很多用户反馈"装了没变化"的真实原因。

### 4.5 `svipm/cursor-i18n-zh` —— 工程化交付

- Rust + Tauri 2 桌面应用，提供图形化"汉化工作台"
- GitHub Actions 中有独立的 `cursor-compat.yml` **兼容性测试流水线**
- 支持 Cursor 与 Claude Desktop

### 4.6 `652036/agent-zh-cn` —— 唯一带跨平台 CI 的项目

- 多软件适配：Devin / Cursor / Windsurf / Antigravity / VS Code
- CI 在 Windows / macOS / Linux 上检查：安装样本、卸载、**故障回滚、运行时内容保护**
- 作者诚实标注"测试通过 ≠ 每个版本都完成逐页验证"

## 5. 社区共识与分歧

### 共识

1. 官方语言包必须装，且**语言包版本要与 Cursor 内核版本对齐**
2. 纯语言包无法覆盖 Cursor 专有 UI，硬编码补丁不可避免
3. 改程序文件后**必须同步 `product.json` 校验值**，否则报"安装已损坏"
4. 必须备份 + 提供还原
5. Cursor 升级后补丁失效，需要重新应用
6. 改完必须**完全退出 Cursor**（含托盘），重载窗口无效

### 分歧

| 议题 | 主张 A | 主张 B |
| --- | --- | --- |
| 语言包形态 | **替代**官方包（polang233，可修路径漂移） | **补充**官方包（LoosePrince，避免冲突） |
| 覆盖方式 | 静态改写 bundle（覆盖高、需重打） | 运行时注入 DOM（升级不易失效、性能差） |
| 词典来源 | 人工维护词库 | AI 自动翻译 / 翻译记忆 |

## 6. 与本蓝图的关系

本次调研的结论**支持并修正**了原蓝图：

| 原蓝图判断 | 调研结论 | 处理 |
| --- | --- | --- |
| 分层模型（NLS / 专有 / 硬编码） | 与 `LoosePrince` 高度一致 | ✅ 保留 |
| 校验算法需重算 | 多个项目独立验证同一做法 | ✅ 保留，本机已复现算法 |
| 预期覆盖 92%+ | 社区实测可达 99.8% | ⚠️ **上调预期** |
| 语言包"补充"官方包 | `id: vscode` 无法共存 → 必须**替代** | ⚠️ **修正** |
| 未提及 `state.vscdb` | 是"没生效"的常见根因 | ➕ **补充** |
| 未提及 `glass.main.js` | 智能体窗口独立 bundle，且**免校验** | ➕ **补充** |
| 未提及升级自动跟随 | 社区已有成熟做法 | ➕ **补充** |
| 从 Cursor 键表反向对齐译文 | `Fish-under-sea/Cursor-IDE-zh-hans` 明确"基于微软 vscode-loc 社区项目开发" | ✅ **路线获独立印证** |
| 检索只用英文关键词 | 中英文查询集合几乎不重叠，单语会漏 1/3 | ⚠️ 已修正 |

**本项目的差异化**：社区项目大多**手工维护词库**（有项目做到 2469 条人工词条）。
本方案改为**从 Cursor 自身 `nls.keys.json` 反推权威键表**，
再用官方译文 + 路径归一化自动对齐，把"人工维护"压缩到真正无解的那部分（约 300 键）。
