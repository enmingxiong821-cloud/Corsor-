## 1. 项目目标与硬约束

### 1.1 目标

把 Cursor 界面的中文覆盖率从当前 **85.43%** 提升到 **95% 以上**，并且：

- 不破坏 Cursor，不影响其正常使用
- Cursor 升级后可以重新应用
- 每一步都可回滚

### 1.2 技术栈（强制）

| 项 | 要求 |
| --- | --- |
| 语言 | **Node.js ≥ 18，ESM（`.mjs`）** |
| 依赖 | 尽量零第三方依赖；确需 zip 能力时最多引入 1 个 |
| 平台 | Windows 优先，路径处理需兼容 macOS / Linux |

> **禁止使用 Python 实现本项目。**
> 实测依据：本机 `python` 被 Microsoft Store 别名劫持，且
> `Python313\python.exe` 被执行策略拒绝（`ResourceUnavailable`）。
> 同样原因，`py -3` 也找不到可用运行时。

### 1.3 硬约束（违反即视为失败）

1. **默认只读**：可写入的只有 `install` / `patch` / `restore`（以及它们被 `sync` / `setup` 自动调用时），其余命令**只能读**
2. **写前必备份**：任何被写入的文件，先复制到备份区并记录原始 SHA-256
3. **必须能完整还原**：`restore` 后文件需与原始版本**字节级一致**
4. **不得破坏校验**：改写被校验文件后，必须同步重算 `product.json` 的 checksums
5. **不碰用户内容**：禁止操作编辑器正文、终端、输入框、`contenteditable`、Monaco、聊天正文
6. **禁用 innerHTML**：CSP 带 `require-trusted-types-for 'script'`，只能用 `textContent`
7. **注入必须同源**：CSP `script-src 'self'` 无 `unsafe-inline`，禁止内联脚本
8. **失败即回滚**：多文件写入过程中任一步失败，按反向顺序恢复

## 2. 关键技术事实速查

实现时会反复用到，务必记住：

### 2.1 Cursor 的三个数据源

| 文件 | 结构 | 说明 |
| --- | --- | --- |
| `out/nls.keys.json` | `[[moduleId, [key, ...]], ...]` | 1,150 模块 / 13,530 键 |
| `out/nls.messages.json` | `[string, ...]`，长度 13,530 | 英文原文，**与上面逐位对应** |
| 语言包 `translations/main.i18n.json` | `{moduleId: {key: 译文}}` | 也可能被包在 `{contents: ...}` 里 |

### 2.2 校验值算法（已实测复现，6/6 匹配）

```js
import { createHash } from "node:crypto";
const digest = createHash("sha256").update(fileBuffer).digest("base64").replace(/=+$/, "");
```

被校验的文件（`product.json.checksums`，相对 `resources/app/out/`）：

```
vs/base/parts/sandbox/electron-sandbox/preload.js
vs/workbench/workbench.desktop.main.js
vs/workbench/workbench.desktop.main.css
vs/workbench/api/node/extensionHostProcess.js
vs/code/electron-sandbox/workbench/workbench.html
vs/code/electron-sandbox/workbench/workbench.js
```

### 2.3 免校验文件（改这些不触发"安装已损坏"）

`workbench.glass.main.js`（智能体窗口）、`workbench.anysphere-ui-automations.js`、
`nls.messages.json`、`nls.keys.json`。

> M4 的三个目标里有两个落在这一档；第三个 `workbench.desktop.main.js` **在上面的被校验
> 清单里**，改写它必须重算 `product.json.checksums` —— 协议见 §7「被校验目标的写入协议」。
> 另有一条**字体通道**改写同样被校验的 `workbench.desktop.main.css`（§4.13），走同一套协议。

### 2.4 路径漂移映射（v1，已实测有效；映射上限 332 键，净救回 328 键）

现象：VS Code 上游把目录 `electron-browser` 重命名为 `electron-sandbox`，
语言包仍按旧路径组织，导致同模块译文全部对不上号（整模块 0% 覆盖）。

查找方向（**注意方向：从 Cursor 现用路径指向语言包中的路径**）：

| Cursor 现用路径片段 | 语言包中的路径片段 |
| --- | --- |
| `electron-sandbox` | `electron-browser` |
| `contrib/search/common` | `contrib/search/browser` |

### 2.5 语言包扩展格式（实测自官方包）

```json
{
  "name": "cursor-language-pack-zh-hans",
  "publisher": "cursor-zh-local",
  "version": "1.0.0",
  "engines": { "vscode": "^1.128.0" },
  "categories": ["Language Packs"],
  "contributes": {
    "localizations": [{
      "languageId": "zh-cn",
      "languageName": "Chinese Simplified",
      "localizedLanguageName": "中文(简体)",
      "translations": [{ "id": "vscode", "path": "./translations/main.i18n.json" }]
    }]
  }
}
```

> **重要**：`id: "vscode"` 的语言包**不能与官方中文包共存**，
> 同装会导致翻译错乱。因此本工具产出的是**替代包**，
> 安装时需提示用户或自动处理官方包的停用。

## 4. 模块规格

每个模块给出：**职责 / 输入 / 输出 / 要点**。

### 4.1 `scan/locate.mjs`

- **职责**：定位 Cursor 安装目录与用户数据目录
- **输出**：
  ```js
  {
    appDir,          // 含 resources/app 的目录（安装根的 resources/app）
    outDir,          // appDir/out
    userDir,         // ~/.cursor
    extensionsDir,   // userDir/extensions
    dataDir          // 平台相关的用户数据目录（见下）
  }
  ```
- **要点**：
  - 优先级：`CURSOR_INSTALL_DIR` 环境变量 → 常见路径探测
  - 常见路径（Windows）：`%LOCALAPPDATA%\Programs\cursor`、`%LOCALAPPDATA%\Programs\Cursor`、`%PROGRAMFILES%\Cursor`
  - 校验依据：目标目录下存在 `resources/app/out/nls.keys.json`
  - 找不到时报错并提示用户设置 `CURSOR_INSTALL_DIR`

> **⭐ `dataDir` 必须按平台分支（2026-10-15 修正）**
>
> `clpDir = dataDir/clp` 是缓存失效的落点，**写错不会报错，只会让缓存失效静默失败**，
> 表现为"改了文件但界面还是英文"。三个平台各不相同：
>
> | 平台 | 路径 |
> | --- | --- |
> | Windows | `%APPDATA%\Cursor` |
> | macOS | `~/Library/Application Support/Cursor` |
> | Linux | `$XDG_CONFIG_HOME/Cursor`（默认 `~/.config/Cursor`） |
>
> 早期实现用 `%APPDATA% || ~/.config`，在 macOS 上会指向不存在的路径。
>
> 早期还返回过一个 `installDir`（`dirname(dirname(appDir))`），该字段**从未被消费**，
> 且在 macOS 候选路径、以及 `CURSOR_INSTALL_DIR` 直指 app 目录时都会算错，已移除。

### 4.2 `scan/keys.mjs`

- **职责**：解析 Cursor 的键表与英文原文，交替展开为扁平数组
- **输出**：
  ```js
  [{ moduleId, key, en }, ...]   // 13,530 条
  ```
- **算法**：
  ```
  keysJson     = JSON.parse(nls.keys.json)      // [[module, [key...]], ...]
  messagesJson = JSON.parse(nls.messages.json)  // [en...]
  i = 0
  for [module, keys] of keysJson:
      for key of keys:
          push { moduleId: module, key, en: messagesJson[i] }
          i += 1
  ```
- **要点**：顺序必须严格对应；建议断言 `i === messagesJson.length`，不等则报错（版本结构可能变了）

### 4.3 `scan/pack.mjs`

- **职责**：解析已安装语言包的 bundle
- **输出**：`Map<moduleId, Map<key, 译文>>`
- **要点**：
  - bundle 可能是 `{contents: {...}}` 或直接 `{...}`，需兼容
  - 忽略空字符串译文
  - 需支持读取 `translations/extensions/*.i18n.json`

### 4.4 `align/normalize.mjs`

- **职责**：对模块路径生成候选变体
- **输入**：`moduleId`、`data/renames.json`
- **输出**：候选 `moduleId` 数组
- **要点**：不要硬编码在代码里，全部从 `renames.json` 读取，便于后续维护

### 4.5 `align/merge.mjs` —— 核心

- **职责**：生成最终的 moduleId → key → 译文 映射
- **算法（严格按此顺序）**：
  ```
  for each { moduleId, key, en } in keys:
      # 1 精确匹配
      if official[moduleId]?.[key] 有非空值:  emit 该译文; continue
      # 2 补译词典（按英文原文细分，不受重名键影响）
      slot = overrides[moduleId]?.[key]
      if slot 是字符串 且非空:      emit; continue
      if slot 是对象 且 slot[en] 存在: emit; continue
      # 3 路径归一化兜底
      for v of normalize(moduleId):
          if official[v]?.[key] 有非空值:  emit; continue 外层
      # 4 记录缺口（不输出）
      missing.push({ moduleId, key, en })
  ```
- **输出**：`{ translations, missing, stats }`
- **要点**：
  - 必须记录每条译文的**来源**（`exact` / `override` / `renamed<from>`），供报告使用
  - 缺口必须导出为工作单，供人工补译
  - 不得自动机器翻译并直接写入产出（避免污染）

> **⭐ 顺序修正（2026-10-15，实测依据，覆盖初版规格）**
>
> 初版把「路径归一化」排在「补译词典」之前，实测证明这会造成**语义错误**，
> 已调整为**归一化仅作兜底**：
>
> | 证据 | 数值 |
> | --- | ---: |
> | 1,971 条缺口中，**同模块内键名重复**的条目 | **273** |
> | 归一化救回的 332 条中占位符不匹配 | 4 |
> | 对照：官方包精确命中的 11,559 条中占位符不匹配 | 21 |
>
> 归一化靠「模块路径 + **键名**」查语言包，而语言包的 bundle 是 `{moduleId: {key: 译文}}`，
> 同模块内的重名键**只能拿到同一个值**。实测索引 11933/11934 同属
> `installActions :: successIn`，英文分别是 "Successfully installed…" 与
> "Successfully unlinked…"，却拿到同一句中文，其中一条语义相反。
>
> 归一化仍保留，用于报告里的投影，以及未来某键缺补译时的兜底。
>
> **⭐ 归一化兜底加了占位符闸（2026-10-15 三次修正）**
>
> 上表那 4 条占位符不匹配的不再被写入：归一化来源的译文**只在占位符编号集合与当前英文
> 一致时才复用**，否则宁可留英文缺口（`stats.renamedRejected` 计数）。
> 原因是硬套会让界面**字面显示 `{0}`**——实测索引 11932 的英文 `"Install 'code' command"`
> 没有占位符，却被套上了含 `{0}` 的中文。加上这道闸后，归一化实际救回 **328** 条，
> 覆盖率投影 87.89% → **87.86%**，这 4 个键改由补译词典覆盖（记入工作单，不会丢）。

> **⭐ 补译词典也必须能区分重名键（2026-10-15 二次修正）**
>
> 上面那句旧的结论——“补译词典是按索引 → 英文原文逐条产出的，不受重名影响”——**是错的**。
> 词典的键是 `moduleId + key`，与归一化一样区分不了重名键。实测那 273 条重名缺口里：
>
> | 分类 | 数量 |
> | --- | ---: |
> | 重名但英文**相同**（一条译文合法共用） | 258 |
> | 重名且英文**互不相同**（一条译文必错一条） | 15 → **8 个索引必错** |
>
> 出错的键恰好都是语义相反或占位符不同的那种：
>
> ```
> installActions :: successIn   "Successfully installed…" / "Successfully unlinked…" / "Shell command…"
> installActions :: install     "Install 'code' command" / "Install '{0}' command"
> debugIcons     :: debugAll    "Icon for the debug function action." / "Icon for the debug stop recording action."
> ```
>
> 因此词典值支持**两种形式**，由 `align/merge.mjs` 的 `overrideFor()` 统一解析，
> `dict/validate.mjs` 与 `dict/assemble.mjs` 共用同一套语义：
>
> | 形式 | 取值 | 语义 |
> | --- | --- | --- |
> | 字符串 | `"译文"` | 该 key 下**所有**索引共用；仅当它们英文相同才正确 |
> | 对象 | `{ "英文原文": "译文" }` | 按英文逐条区分，**重名键的唯一正确写法** |
>
> `assemble` 会在「字符串落到多条不同英文上」时显式报出**歧义键**，
> 并把这类键自动改写成对象形式，不会静默一译多用。

### 4.6 `align/report.mjs`

- **职责**：生成覆盖率报告
- **输出**（同时打印与写文件）：
  ```
  总键数 / 精确命中 / 归一化命中 / 补译命中 / 缺口
  覆盖率 = (总键数 - 缺口) / 总键数
  缺口按模块分组 Top N（附英文原文样例）
  ```
- **要点**：报告写入 `reports/coverage-<cursorVersion>.json`，便于版本间对比

### 4.7 `pack/build.mjs`

- **职责**：产出可直接安装的语言包扩展目录
- **输出**：`pack/cursor-zh-hans/{package.json, translations/main.i18n.json}`
- **要点**：
  - `main.i18n.json` 结构：`{ moduleId: { key: 译文 } }`
  - `engines.vscode` 取当前 Cursor 的 `product.json.vscodeVersion`
  - JSON 必须 UTF-8、不转义中文（`JSON.stringify(obj, null, 2)`），
    但**注意**：中文里若出现全角引号 `""` 会让 JSON 校验失败，需在词典校验阶段拦截
  - 建议同时输出统计信息

### 4.8 `dict/load.mjs` + `dict/validate.mjs`

- **职责**：加载与校验补译词典
- **校验项**（任一失败即报错并指出具体条目）：
  1. 译文不得为空
  2. 原文与译文的 `{0}` `{1}` 等占位符**编号集合**必须一致（顺序可变）。
     重名键（同一 moduleId+key 多条英文）**逐条按各自英文校验**，不能只校验碰巧排在最后的那条
  3. 含 `&&` 的助记符：**不作为错误**。`align/mnemonic.mjs` 会按官方风格统一改写成
     `译文(&&X)`（大写原字母），实测官方包 348 条带 `&&` 的译文里 299 条是这个形式
  4. ~~译文中的 JSON 合法性（无非法引号）~~ —— **已作废**，见 §8 第 5 条：
     全角引号合法，只作风格提示
  5. 同一 moduleId+key 不得重复定义（JSON 对象天然保证，仅需防手写文件的重复行）
  6. 键不在当前 Cursor 键表中 → 告警（升级后可能残留），不阻塞
  7. 重名键用字符串形式 → 告警（会一译多用）；对象形式漏掉某条英文 → 告警（会留英文缺口）

### 4.9 `deploy/backup.mjs`

- **职责**：版本化备份
- **输出**：
  ```
  backup/<cursorVersion>_<distro>/
  ├── manifest.json          # 文件清单 + 原始 SHA-256 + 时间戳
  └── files/<相对路径>
  ```
- **要点**：
  - **按 version+distro 分目录**，绝不用旧版本的备份覆盖新版本文件
  - `manifest.json` 记录每个文件的原始 hash，供还原时比对

### 4.10 `deploy/checksum.mjs`（**未实现**；实际实现见 §4.13 的 `m4/integrity.mjs`）

- **职责**：重算并写回 `product.json` 的 checksums
- **算法**：见 §2.2
- **要点**：
  - **只在对应文件写入成功后**才更新该文件的校验值（避免校验值领先于内容）
  - 写回时保持 `product.json` 原有格式（缩进 `\t`，实测为 tab 缩进）
  - 更新前对 `product.json` 自身也做备份
- **状态**：NLS 通道不需要它（那是免校验路径），所以 `deploy/checksum.mjs` 从未创建；
  唯一需要它的是 M4 的被校验目标（内核 bundle + 字体 CSS），落地在 `src/m4/integrity.mjs`：
  上述三条要点照办，另加「写前断言格式未变」与「写后重算全部 6 个被校验文件」两道闸门。

### 4.11 `deploy/install.mjs`

- **职责**：把改写后的 `out/nls.messages.json` 写进 Cursor，并失效 clp 缓存
- **步骤**：
  1. 取基准表 —— **一律用备份里的原始英文表**（`baselineTable`，见 §4.5），不用盘上当前那份：
     装过之后它已经是中文，拿它当「英文原文」会凭空报出缺口。真要退回盘上那份时，
     先用 `looksTranslatedTable` 确认它确实是英文表，否则明确告警「本轮数字不可信」
  2. 计算本轮消息表（`buildPatchedMessages`）：**最小改动**，只动目标索引
  3. **三重守卫**（缺一个都可能污染原始基准）：
     - 当前文件既不等于 `entry.sha256`（原始）也不等于 `entry.installedSha256`
       （本工具上次写入的）→ 拒绝写入
     - 备份里没有它的条目、而它又已是中文（`looksTranslatedTable`）→ 拒绝写入
       —— 否则会把中文存成「原始备份」，`restore` 将把中文原样「还原」回去
     - `dryRun` 时不进入任何守卫分支，只报告「将备份 / 将写入」
  4. 备份（`ensureBackupEntry`，缺条目则补上）→ 写同目录临时文件 → 原子改名
  5. 回填 `installedSha256`，失效 clp 缓存（`cache.mjs`；失败则把文件回滚成备份原文）
- **要点**：本通道**不装语言包、不写 `argv.json`、不重算任何哈希**。
  原设计的「复制语言包扩展 + 改 `locale`」路线已被 §2.3 的免校验通道取代，
  `src/pack/*` 与 `deploy/checksum.mjs` 因此从未实现（见 §4.7、§4.10）。

### 4.12 `deploy/restore.mjs`

- **职责**：还原到应用前状态
- **步骤**（三态判定，见 §5.4 与 §6.3）：
  1. 读取 `manifest.json`
  2. **逐文件比对当前 hash**：
     - 等于 `entry.sha256` → 已是原始内容，无需还原
     - 等于 `entry.installedSha256` → 确认是本工具改的，安全还原
     - 两者都不等（含 `installedSha256` 缺失）→ **跳过该文件并警告**（可能已被 Cursor 升级器更新）
  3. 还原后复查哈希，不符即抛错
  4. 清掉该文件的 `installedSha256`
  5. 失效 clp 缓存

### 4.13 `m4/*`（AI 面板 bundle 改写，已实现）

原设计的「向 `workbench.html` 注入运行时脚本 + 重算 checksum」**未被采用**。改走离线替换，理由见 M4 一节：
两个 Cursor 自有的 AI 面板 bundle 不在 checksums 清单里，直接改它们既不注入脚本、不碰 CSP。

> **但另外两个目标必须动被校验文件**：内核 bundle `workbench.desktop.main.js` 与字体通道用的
> `workbench.desktop.main.css` 都在 checksums 清单里，改写后必须重算 `product.json` 并过
> 6 文件完整性闸门（`integrity.mjs`），闸门不过即同时回滚文件与 `product.json`。协议见 §7。

- `fields.mjs`：`UI_FIELDS` 白名单（`label`/`children`/`description`/`placeholder`/`tooltip` …）
  与 `NEVER_FIELDS` 黑名单（`value`/`id`/`command`/`key`/`url`/`path` …）
- `scan.mjs`：扫字符串字面量 → 形状判据（长度、纯可打印 ASCII、含空格、首字母大写…）
  → 往前看 40 字符取字段名 → 白名单命中且不在 NLS 基准表里才算候选
- `patch.mjs`：按 `start`/`end` 逐处替换（**不是全文 replace**），转义引号后写回
- `deploy.mjs`：`node --check` 全量语法校验 → 备份 → 写同目录临时文件 → 原子改名；
  被校验目标再走 `integrity.mjs` 重算校验值并过闸门，不过则 `rollbackAndThrow`
- `integrity.mjs`：`applyChecksumUpdates` 只改目标键的值（写前断言 `product.json` 恰为
  `JSON.stringify(obj, null, "\t")`，避免顺手重排整份文件），写后 `assertIntegrity` 把 6 个
  被校验文件全部重算一遍
- `deploy.mjs` 另有 **`healHalfWritten` 半成品自愈**：上一次写到一半（进程被杀 / 断电 /
  回滚自身失败）会留下「文件已改 + 校验值过期」，而重跑又会因文件里已无可替换英文而走
  `no-change` 分支，永远补不上 —— 于是每 15 分钟的自动 `sync` 也修不回来。自愈只认
  「当前哈希 == 本工具上次写入的哈希」这一种，确认是自己的半成品才补算，别的工具改过的一律
  不碰，交给闸门报错
- `fontfix.mjs`：字体通道（见 M4 一节），改写 `workbench.desktop.main.css`：末尾追加
  `--vscode-font-family` 定义；幂等靠 CSS 里的标记行 `/* cursor-zh-fontfix */`
- `nlsbase.mjs`：取**备份里的原始英文 NLS 表**作为内核目标的排除基准；缺备份时
  返回 `null`，让内核目标被**跳过**而不是硬改（理由见 §7）

保留的旧设计约束（仍然成立）：不得触碰 input / textarea / contenteditable / Monaco / 终端 / 聊天正文。
现在的实现方式让这条约束变成了结构性的 —— 改的是字符串常量，运行时行为不变。

### 4.15 ★ NLS 免校验通道（本方案的实际写入路径，取代原 M2 的"语言包"路线）

**结论先行**：不需要生成语言包、不需要 VSIX、不需要碰任何被校验文件。
改写一个 665 KB 的**免校验**文件 + 失效缓存即可。

依据（`docs/03` §1.1 源码级确证）：运行时合并规则是

```js
out.push(mod?.[key] || defaultMsgs[i]);   // 语言包优先，缺失才回退默认表
```

而 `out/nls.messages.json`（`defaultMsgs`）**不在 `product.json.checksums` 覆盖范围内**。

因此：

| 步骤 | 模块 | 说明 |
| --- | --- | --- |
| 1 | `deploy/nls.mjs` | 只把「语言包未覆盖」的索引替换成中文，其余保持**字节不变** |
| 2 | `deploy/backup.mjs` | 改前备份，记录原始 SHA-256（hex） |
| 3 | `deploy/install.mjs` | 备份 → 校验未漂移 → 临时文件 + rename 原子写入 → 失效缓存 |
| 4 | `deploy/cache.mjs` | ★ **不失效缓存就等于没装**，见下 |

**★ 为什么必须失效缓存**

运行时真正读的是缓存文件，不是语言包，也不是默认表：

```
%APPDATA%\Cursor\clp\<语言包hash>.zh-cn\<Cursor commit>\nls.messages.json
```

`out/main.js` 里的生成函数只要发现该 commit 目录存在就**直接返回**，
**根本不会重读 `nls.messages.json`**（`if (await exists(m)) return Edt(m)`）。
这既是"汉化没生效"的真实根因，也是本方案唯一必须处理的副作用。

失效手段（`deploy/cache.mjs` 采用后者）：

| 手段 | 做法 | 风险 |
| --- | --- | --- |
| 删除缓存目录 | 删 `clp\<hash>.zh-cn\<commit>\` | 低（Cursor 自动重建） |
| **投放损坏标记** | 在 `clp\<hash>.zh-cn\` 放空文件 `corrupted.info` | **更低——Cursor 自带的修复通路，整目录重建** |

**不做的事**

- ❌ 不生成语言包 / 不装 VSIX —— `id:"vscode"` 的包与官方中文包冲突（§2.5），而改写默认表无此问题
- ❌ 不改 `product.json.checksums` —— 被改的文件本就不在校验范围内
- ❌ 不改 `argv.json` —— 语言已是 `zh-cn`，无须再设

**收益**：M2 的最坏风险从"改 39.8 MB 主 bundle + 重算校验"降到"改一个免校验 JSON + 清缓存"。
**代价**：必须完全退出 Cursor 再启动（重载窗口无效），且每次 Cursor 升级后要重跑一次。

### 4.16 `sync` —— 自动跟随 Cursor 升级

**要解决的问题**：代价那半句。Cursor 每次升级都会把 `out/nls.messages.json` 换回英文原文，
且新版本落在**新的备份目录**（`backup/<version>_<distro>/`）下。手工记得重跑 `install` 不现实。

`sync` 把「判断」与「写入」分开，判断部分全部只读：

| 磁盘状态 | 判定依据 | 动作 |
| --- | --- | --- |
| 已是最新 | `当前哈希 == manifest.installedSha256` | 无（快速路径，几毫秒） |
| 被换回原始内容 | `当前哈希 == manifest.sha256` | 重新写入 |
| 新版本 / 首次 | 当前版本的 `manifest.json` 不存在 | 重建译文表后写入 |
| 被第三方改动 | 两个哈希都不等 | **跳过并告警，退出码 1** |

关键约束：

- **Cursor 运行中绝不写入**（`tasklist` 探测 `Cursor.exe`）。文件被占用，且缓存失效会在错误时机生效。
  探测失败（拿不到结果）同样跳过 —— 不在不确定时写入。`--dry-run` 全程不落盘，故不受此限。
- 译本生成（`prepare`）在内存完成，`validateOverrides` / `validateResolved` 失败就中止，
  一个字节都不写。新版本键表与现有词典不匹配时，Cursor 保持原样并留日志。
- 基准表优先取备份里的原始 `nls.messages.json`，保证反复执行结果完全一致（幂等）。
- 第三态（被第三方改动）**绝不自动覆盖** —— 那可能是升级器的中间态，覆盖会毁掉安装。
- 每次执行都追加 `logs/sync.log`（超 1 MB 轮转一份 `.1`）。

**计划任务**（`scripts/`）：

| 文件 | 作用 |
| --- | --- |
| `register-task.ps1` | 注册 `CursorZhAutoSync`：登录时 + 每 15 分钟 |
| `unregister-task.ps1` | 注销该任务（不动已装译文） |
| `sync-hidden.vbs` | `wscript.exe` 静默拉起 `node src/cli.mjs sync`，无控制台窗口，stderr 落 `logs/sync.out` |

任务是**交互式 + 普通权限**（`-RunLevel Limited`），不请求提权、不写系统目录。

## 5. 数据结构定义

### 5.1 `data/overrides.json` — 补译词典

人工维护，初始为 `{}`。键为 moduleId，值为 key → 译文；译文可以是**字符串**或**对象**：

```json
{
  "vs/workbench/contrib/cursorBlame/browser/cursorBlame.contribution": {
    "cursorBlame.openFileBlameTitle": "打开文件溯源",
    "cursorBlame.category": "代码溯源"
  },
  "vs/workbench/browser/windowQuitConfirmation": {
    "quitConfirmationTitle": "退出 Cursor？"
  },
  "vs/workbench/electron-sandbox/actions/installActions": {
    "install": {
      "Install 'code' command": "安装 'code' 命令",
      "Install '{0}' command": "安装 '{0}' 命令"
    }
  }
}
```

- **字符串**：该 key 下的所有索引共用这条译文。适用于英文相同的重名键，也是绝大多数情况。
- **对象**：`{ 英文原文: 译文 }`，按英文逐条区分。**同一个模块内出现同名 key 且英文不同时，
  必须用这种形式**，否则 8 个索引会拿到与自身语义不符的译文（详见 §4.5 二次修正）。

> 现有缺口工作单见 `build/missing.json`（按模块分组，含英文原文），
> 可直接作为翻译输入，翻译完用 `assemble` 转成上面的格式放入 `data/`。

### 5.2 `data/renames.json` — 路径归一化映射

```json
{
  "description": "把 Cursor 现用模块路径还原为语言包中的旧路径，用于复用官方译文",
  "rules": [
    { "from": "electron-sandbox", "to": "electron-browser" },
    { "from": "contrib/search/common", "to": "contrib/search/browser" }
  ]
}
```

> 注意方向：`from` 是 Cursor 用的路径，`to` 是语言包里的路径。

### 5.3 `data/terms.json` — 术语表

供人工翻译与 AI 补译时保持一致，**程序不做强制文本替换**（仅可选用作一致性检查）。
权威文件见 `data/terms.json`，完整对照表见 04 文档 §5。

结构（注意：`keepAsIs` 与 `terms` 是**两个不同语义的字段**，不可合并）：

```json
{
  "_note": "……",
  "keepAsIs": ["Cursor", "Composer", "Glass", "Notepad", "Cursor Tab", "MCP", "Token"],
  "terms": {
    "Agent": "智能体",
    "Subagents": "子智能体",
    "Rules": "规则",
    "Skills": "技能",
    "Hooks": "钩子",
    "Tools & MCP": "工具与 MCP",
    "Tab": "选项卡",
    "Blame": "溯源"
  }
}
```

> **两条易错点（初版曾错，务必遵守）**：
>
> 1. `Composer` 属 `keepAsIs`，**不是** `"编辑器"`。译成「编辑器」会与 VS Code 原生
>    Editor 的通用译名冲突，用户无法判断指代。
> 2. `Tab` 与 `Blame` 是**歧义词，必须分治**：`Tab` 只在标签页语义下译「选项卡」，
>    指 Cursor Tab 补全功能时保留原文；`Blame` 只在通用 git blame 语义下译「溯源」，
>    Cursor 自研的 `Cursor Blame` 保留原文。一刀切会在两个方向同时出错。

### 5.4 `backup/<version>_<distro>/manifest.json`

```json
{
  "cursorVersion": "3.24.18",
  "distro": "be4c9e5350d77747b42cd467cbd3370a753d4640",
  "createdAt": "2026-10-15T12:00:00.000Z",
  "files": [
    {
      "relativePath": "out/nls.messages.json",
      "sha256": "059f196f84c605b0cf69a1a303e32e0c9c5a16cc639a61b460ccadb43e3381c5",
      "size": 664892,
      "installedSha256": "3b1f0c9a7e2d4e68b5a0f3c2d1e4a6b7c8d9e0f1a2b3c4d5e6f708192a3b4c5d",
      "installedAt": "2026-10-15T12:05:00.000Z"
    }
  ]
}
```

`sha256` 为 hex 形式（完整 64 字符），与 `product.json` 里的 base64 形式不同——
内部校验用 hex，写回 `product.json` 时用 base64 去 padding。

**`installedSha256` 是还原安全的唯一依据**，由 `install` 写入成功后回填：

| 当前文件等于 | 判定 | 动作 |
| --- | --- | --- |
| `sha256` | 已是原始内容 | 无需还原 |
| `installedSha256` | 确认是本工具改的 | 安全还原 |
| 两者都不等 | 可能被 Cursor 升级器换过 | **跳过并告警**，绝不用旧备份覆盖 |

没有这个字段时只能比对 `sha256`，会同时导致两个 bug：`restore` 永远判成"外部改动"
而拒绝还原（写回成死代码）、`install` 第二次执行把自己上次的产出误判成外部改动而中止。

> **`distro` 字段实测为空（2026-10-15）**：Cursor 3.24.18 的 `product.json` **没有**
> `distro` 键，早期文档里那个 `d5c0e77a…` 是别处的值。同一构建的标识只能取 `commit`
> （`readProduct()` 里做 `p.distro || p.commit`），这也是 clp 缓存目录的分层依据。
> `backupRoot()` 对缺失值直接报错，避免再出现 `backup/undefined_<distro>/` 这种目录。

## 6. 关键算法伪代码

### 6.1 校验值计算（务必先写单测验证）

```js
function base64Sha256(buf) {
  return createHash("sha256").update(buf).digest("base64").replace(/=+$/, "");
}
```

**金标准断言**（用本机真实文件验证，必须通过）：

```
base64Sha256(workbench.html) === "BZ8Zb4TGBbDPaaGjA+MuDJxaFsxjmmG0YMyttD4zgcU"
base64Sha256(workbench.desktop.main.js) === "7Wkip6hsjESKRqo5rwyTFYDaFidw/kBqDUFzcpDmN9k"
```

> 若这两个断言不通过，说明算法写错了，**不要继续往下做**。

### 6.2 事务式多文件写入

```
写入前：
  plan = [{ path, newContent }]         # 全部先在内存中生成
  对 plan 里每个 path：备份 → 记录 hash
执行：
  已写入 = []
  try:
      for item of plan: 写文件; 已写入.push(item)
      重算并写回 product.json checksums   # 必须在所有目标文件写成功之后
  catch:
      按 已写入 的反向顺序恢复
      抛出错误
```

### 6.3 安全还原

```
for entry of manifest.files:
    if 备份文件缺失或自身 hash !== entry.sha256:
        警告：备份已损坏，跳过
        continue
    当前hash = sha256(currentFile)
    if 当前hash === entry.sha256:
        已是原始内容，无需还原
        continue
    if 当前hash !== entry.installedSha256:        # 含 installedSha256 缺失的情况
        警告：文件已被外部修改（很可能是 Cursor 升级），跳过
        continue
    用备份覆盖
    校验覆盖后 hash === entry.sha256（不符即抛错）
    把 installedSha256 置空
```

**第二轮修正**（2026-10-15 下半天，起因是用户报「agent 汉化不行」）。上一轮的四条规则只管

排查后发现漏的是**四种别的语法形态**，以及**两处会真出错的解析**：

5. **`title:{value,original}` 成对结构**。这类对象形如
   `title:{value:"Open Settings",original:"Open Settings"}`，`value` 自己就在
   `NEVER_FIELDS` 里（它更多时候是普通数据字段），所以字段白名单永远放行不了。
   新增 `TITLE_OBJ_RE` 单独识别：只有 `value` 与 `original` **并存且相等**时才收 ——
   这是 VS Code 那套「原文 / 译文」结构的签名，普通数据对象不会长这样。
6. **设置页的左导航映射表**。Agent 窗口 Settings 的左栏 13 个条目来自**一个 24 成员的
   对象字面量** `TNn={general:"General",profile:"Profile",…}`。它的键是小写 id
   （`general` / `appearance` / `models`…），与 `UI_FIELDS` 里任何一个都不沾边，
   于是整张表被静默跳过 —— 这正是「设置页左边全是英文」的直接原因。新增
   `NAV_MAP_RE` / `NAV_ENTRY_RE`：认出「≥5 个成员、每个成员的值都是文案」的对象，
   对其中**值**逐个处理，且仍受 `NEVER_FIELDS` 与本文件末的标识值守卫约束。
7. **兜底默认值与三元分支**。`label: e.title || "Untitled"`、`text: x ?? "New Chat"`
   这类写法里，`||` / `??` 右侧的文案不在任何字段名右边；`cond ? "This PC" : "This Mac"`
   同理。新增 `FALLBACK_RE` 与 `TERNARY_RE` 分别覆盖。
   三元那条有个**必须成对**的约束：只有当**两个分支都是 UI 文案**时才整体处理 ——
   否则会把 `e?"Top":"InlineStart"` 这类「一边是枚举值、一边是显示名」的三元式翻坏。
   由此 `This PC` / `This Mac` 仍**未翻**（它们所在的是一条链式三元

   连续成对，规则覆盖不到）—— 这是**已知残留**，不是遗漏。
8. **模块级常量被变量声明列表挡住**。`var Sye,n_s,i_s` 这种声明列表中，

   同样是**已知残留**。
9. **映射表的替换区间必须从条目末尾回推**。定位命中区间时若用
   `条目.indexOf(值)` 找引号，当**键也带引号**时（`{"aria-label":"Pinned"}`）会先命中
   **键**的开引号，替换区间起点落到 `"aria-la` 上，改写后把键截断、bundle 语法直接崩。
   实测在干跑阶段被 `assertSyntax` 拦下（6 处 / 文件），未造成实际损坏。
   正确做法是从条目末尾回推：`起点 = 条目起点 + e[0].length - (引号 + 值 + 引号).length`
   —— 映射条目恰好以**值的收引号**结束，回推恒精确。回归测试锁死了「命中区间必须
   精确套住那个字面量」这条不变量。
10. **三元 / 兜底命中的位置没有字段可查**，标识值守卫无从下手。新增 `cmpAny`：

## 8. 常见陷阱（均为实测踩过或社区反馈）

1. **checksums 必须去掉 base64 的 `=` 填充** —— 直接对比会全部不匹配
2. **`argv.json` 是 JSONC** —— 含 `//` 注释，`JSON.parse` 会直接抛错，需先剥离注释或做字段级替换
3. **语言包冲突** —— `id: "vscode"` 的包与官方中文包不能共存，同装会乱
4. **`state.vscdb` 缓存** —— 汉化"看起来没生效"多半是它，部署流程应包含清理步骤并提示用户
5. ~~**中文全角引号 `“”` 会让 JSON 失效**~~ —— **此条已作废（2026-10-15 实测纠正）**。
   `“`(U+201C) / `”`(U+201D) 是普通 Unicode 字符，在 JSON 字符串里完全合法，
   `JSON.stringify` 正确处理。真正会让 JSON 失效的只有 ASCII 双引号 `"` 未转义。
   实测：官方 zh-hans 语言包在 11,559 条精确命中的译文里用了 **928 处**全角引号，
   且 Cursor 渲染正常。故词典校验**不再**把全角引号当错误，仅计入风格提示。
6. **`product.json` 使用 tab 缩进** —— 写回时保持原格式，避免整文件 diff 噪声
7. **不要用 Python** —— 见 §1.2
8. **只读命令不得产生副作用** —— `scan` 绝不能顺手"修复"什么
9. **Cursor 必须完全退出**（含托盘进程）语言才会重新加载，重载窗口无效

## 10. 明确不要做的事

- ❌ 不要把机器翻译结果直接写入产出（必须经过人工确认或标记为待审）
- ❌ 不要修改编辑器正文、终端、输入框、`contenteditable`、Monaco、聊天正文
- ❌ 不要用 `innerHTML` / `outerHTML` / `insertAdjacentHTML`
- ❌ 不要在没有备份的情况下写入任何文件
- ❌ 不要跨版本复用备份（旧备份覆盖新 bundle 会导致 Cursor 无法启动）
- ❌ 不要在未显式确认时执行 `patch`
  （例外：`sync` / `setup` 自动调用 `patch` 是用户 2026-10-15 明确授权的自动跟随通道；
  手工执行仍必须带 `--yes`，否则只允许 `--dry-run`）
- ❌ 不要为了让覆盖率数字好看而伪造译文（宁可留缺口并报告）
